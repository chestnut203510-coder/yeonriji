# DEVELOPMENT RULES

항상 아래 순서를 따른다.

① 현재 프로젝트 구조 분석

② 필요한 폴더 확인

③ 필요한 파일 확인

④ 수정되는 파일 설명

⑤ 영향 범위 설명

⑥ 코드 생성

⑦ 자체 코드 리뷰

⑧ 오류 가능성 점검

⑨ 실행 방법 안내

컴포넌트 규칙

하나의 컴포넌트는 하나의 역할만 수행한다.

300줄이 넘으면 분리한다.

UI와 비즈니스 로직을 분리한다.

- 다른 파일과의 관계

를 먼저 설명한다.
